DalCTF 2026: [Crypto] LCG Seed Squared — Predictable PRNG and Known-Plaintext Attack

Oct 17, 2026 · M0x46 · 5 min read

Crypto PRNG DalCTF 2026
Summary: I solved LCG Seed Squared by exploiting a weakness in its custom encryption scheme. Using the known first character of the flag, I recovered the generator's initial state, reproduced the sequence, and decrypted the complete flag with Python.

Challenge Overview

LCG Seed Squared was a cryptography challenge from DalCTF 2026.

The challenge provided a custom pseudo-random number generator and a file containing encrypted numerical values.

Each flag character was converted to its ASCII value and multiplied by a generated number. The objective was to reverse this process and recover the original flag.

Recon and Analysis

The encryption worked by multiplying the ASCII value of each character by the current pseudo-random state. 

encrypted_value = ord(character) * x

After encrypting each character, the state was updated with the following function: 

def rng(y):
    x = pow(
        int((175*y + 17)/14 + 45),
        15,
        4294967295
    )
    return x

Python's three-argument pow() performs modular exponentiation: 

pow(base, exponent, modulus)

# Equivalent to:
(base ** exponent) % modulus

Although the challenge was named LCG Seed Squared, this update function was not a standard linear congruential generator. The important part was that every new state could be calculated from the previous state.

Root Cause

The encryption exposed the internal state whenever the corresponding plaintext character was known. 

ciphertext[i] = ord(plaintext[i]) * state[i]

state[i] = ciphertext[i] / ord(plaintext[i])

Since the expected flag format starts with "DalCTF{", the first character is "D". 

ord("D") = 68

By dividing the first ciphertext integer by 68, I could recover the first state.

Once this state was known, the deterministic generator could reproduce the entire sequence.

Full Exploit Script

I automated the decryption using Python. The script reads output.txt, recovers the first state, and decrypts every character.

solve.py

#!/usr/bin/env python3

MOD = 4294967295
KNOWN_PREFIX = "DalCTF{"

def rng(y):
    x = pow(
        int((175*y + 17)/14 + 45),
        15,
        MOD
    )
    return x

def read_ciphertext(path):
    with open(path, "r") as f:
        return [
            int(line.strip())
            for line in f
            if line.strip()
        ]

def recover_initial_state(enc):
    first_char = ord(KNOWN_PREFIX[0])

    assert enc[0] % first_char == 0

    state = enc[0] // first_char
    return state

def decrypt(enc, state):
    plaintext = []

    for i, value in enumerate(enc):
        if state == 0:
            raise ValueError("Invalid PRNG state")

        assert value % state == 0

        ascii_value = value // state
        character = chr(ascii_value)

        plaintext.append(character)

        print(
            f"[{i:02d}] "
            f"state={state} "
            f"ascii={ascii_value} "
            f"char={character}"
        )

        state = rng(state)

    return "".join(plaintext)

def main():
    print("[+] Reading ciphertext")

    enc = read_ciphertext("output.txt")

    print(f"[+] Encrypted values: {len(enc)}")

    state = recover_initial_state(enc)

    print(f"[+] Initial state: {state}")
    print("[+] Starting decryption")

    flag = decrypt(enc, state)

    assert flag.startswith(KNOWN_PREFIX)
    assert flag.endswith("}")

    print("\n[+] FLAG:")
    print(flag)

if __name__ == "__main__":
    main()

Why This Attack Works

A deterministic generator is not automatically insecure, but the challenge used its output in a way that directly leaked internal state.

Multiplication by a known ASCII character could be reversed with a simple division. Once one state was recovered, the next states could be calculated without knowing the original seed generation process.

No brute force was required. The attack only needed one known plaintext character, its ciphertext value, and the generator update function.

Takeaways

  • Custom encryption based on simple multiplication is insecure.
  • Known plaintext can expose internal PRNG states.
  • Deterministic sequences can be reproduced after recovering a state.
  • Integer division can reverse this challenge's encryption.
  • Real applications should use established cryptographic algorithms.
