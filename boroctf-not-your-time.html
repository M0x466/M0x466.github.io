boroCTF 2026: [Reverse] Not Your Time — Reversing Bitwise NOT Flag Obfuscation

Oct 17, 2026 · M0x46 · 4 min read

Reverse Bitwise NOT boroCTF 2026
Summary: The Not Your Time binary hid its expected input inside an array of encoded bytes. By analyzing the validation logic, I identified a bitwise NOT operation. A short Python script was enough to recover the complete flag without brute force.

Challenge Overview

Not Your Time was a Reverse Engineering challenge from boroCTF 2026.

The challenge provided a compiled executable that accepted user input and compared it against a hidden value.

Instead of storing the correct input as plaintext, the program encoded its characters using a bitwise operation.

Our objective was to recover the correct input by analyzing the executable.

Recon and Analysis

I started by inspecting the executable using basic Linux tools. 

file chall
strings -a chall

The file command identifies the binary format and architecture, while strings searches for readable text.

Dynamic tracing can also help understand the program's behavior: 

ltrace ./chall

However, the flag was not directly visible as a readable string, so I moved to static analysis of the input validation routine.

Static Analysis

Inside the validation logic, I found an array containing 25 encoded values. 

unsigned char data[] = {
    157, 144, 141, 144, 188,
    171, 185, 132, 177, 207,
    139, 160, 145, 176, 212,
    160, 139, 183, 204, 160,
    185, 179, 191, 152, 130
};

The program applied a bitwise NOT operation to the encoded bytes before comparing them with the user's input.

The logic can be simplified to:

unsigned char decoded = ~data[i];

if (input[i] != decoded) {
    return 0;
}

This means the expected input was not encrypted. It was simply obfuscated with a reversible transformation.

Understanding Bitwise NOT

The bitwise NOT operator (~) flips every bit of a number. 

Original byte:
10011101

After NOT:
01100010

The first encoded value was 157 (0x9d). Applying bitwise NOT gives: 

decoded = (~157) & 0xFF

print(decoded)
print(chr(decoded))

Output:

98
b

The first decoded character was "b", which matched the expected flag prefix boroCTF{.

Exploitation

1. Testing the Transformation

I first tested the transformation on four encoded bytes. 

data = [157, 144, 141, 144]

for value in data:
    decoded = (~value) & 0xFF
    print(value, "->", decoded, "->", chr(decoded))

Output:

157 -> 98 -> b
144 -> 111 -> o
141 -> 114 -> r
144 -> 111 -> o

The decoded text started with "boro", confirming the hypothesis.

2. Decoding the Complete Array

data = [
    157,144,141,144,188,
    171,185,132,177,207,
    139,160,145,176,212,
    160,139,183,204,160,
    185,179,191,152,130
]

flag = ""

for value in data:
    flag += chr((~value) & 0xFF)

print(flag)

This script applies the transformation to all 25 bytes and reconstructs the flag.

Full Solver

I also wrote a reusable version using XOR with 0xFF, which is equivalent to bitwise NOT for 8-bit values.

solve.py

#!/usr/bin/env python3

encoded = [
    157,144,141,144,188,
    171,185,132,177,207,
    139,160,145,176,212,
    160,139,183,204,160,
    185,179,191,152,130
]

def decode(data):
    result = bytearray()

    for value in data:
        decoded = value ^ 0xFF
        result.append(decoded)

    return result.decode("ascii")

def main():
    print("[+] Starting decoder")
    print(f"[+] Encoded bytes: {len(encoded)}")

    flag = decode(encoded)

    assert flag.startswith("boroCTF{")
    assert flag.endswith("}")

    print(f"[+] Decoded flag: {flag}")

if __name__ == "__main__":
    main()

These expressions are equivalent:

(~value) & 0xFF
value ^ 0xFF

Alternative: Solving in C

The same transformation can be reversed directly in C. 

#include <stdio.h>

int main() {
    unsigned char data[] = {
        157,144,141,144,188,
        171,185,132,177,207,
        139,160,145,176,212,
        160,139,183,204,160,
        185,179,191,152,130
    };

    int len = sizeof(data) / sizeof(data[0]);

    for (int i = 0; i < len; i++) {
        unsigned char c = ~data[i];
        printf("%c", c);
    }

    printf("\n");
    return 0;
}

Compile and run:

gcc decode.c -o decode
./decode

Takeaways

  • Bitwise obfuscation is not encryption.
  • Static analysis can reveal hidden constants.
  • Known flag prefixes can help verify decoding.
  • XOR with 0xFF is equivalent to 8-bit NOT.
  • A small Python decoder can be enough to solve a reversing challenge.
